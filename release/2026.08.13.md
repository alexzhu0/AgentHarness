## Migration outcome

- Installed and enabled the official WSL Codex plugin
  `superpowers@openai-curated`, version `11c74d6b`.
- Verified the installed `using-superpowers`, `brainstorming`,
  `writing-plans`, `test-driven-development`,
  `requesting-code-review`, and `verification-before-completion` skills.
- Previewed OMX cleanup with `omx uninstall --dry-run --verbose`, then used
  `omx uninstall --verbose` to remove OMX-managed Codex hooks, configuration
  overlays, 29 skills, 37 prompts, 22 native agent configurations, and the
  global OMX `AGENTS.md`.
- The OMX cleanup removed Codex's Superpowers registration while preserving its
  plugin cache. Re-running the official `codex plugin add` command after OMX
  cleanup restored the final installed/enabled state.
- Moved remaining `~/.codex/.omx` and `~/.omx` state to the private persistent
  directory
  `~/.local/state/agentharness/migrations/2026-08-13-omx-retirement/`.
- Removed global npm package `oh-my-codex@0.20.3`; npm removed 95 packages and
  `omx` is no longer on `PATH`.
- Moved AgentHarness `.omx/state`, `hud-config.json`, `setup-scope.json`,
  and `metrics.json` to the `repository-runtime/` directory under that private
  retirement path.
- Set the retirement tree's directories to mode `0700` and files to mode
  `0600`; a recursive permission probe found no exceptions.
- Preserved ignored AgentHarness `.omx/plans`, `.omx/context`, and
  `.omx/logs` as historical evidence. No new work may use them as active
  workflow state.
- Preserved a user-owned Codex trust entry for the local
  `oh-my-codex` source checkout. A project trust entry is not an OMX hook,
  plugin, executable, package, skill, prompt, agent, or runtime state.
